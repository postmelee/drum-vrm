# 캐릭터 모델 준비하기

[English](models.md) · [README](../README.ko.md) · [엔지니어링 근거](research/vrm-models.md)

확인일: **2026-10-24**. 현재 개발 브랜치는 #17/#18/#30의 로컬 **VRM 1.0** 캐릭터 불러오기를 추가합니다. 아직 **미출시** 기능이며, 공개 v0.2.0 앱은 자체 스켈레톤을 사용하고 VRM 캐릭터를 불러오지 못합니다. 외부 아바타는 배포물에 포함하지 않습니다. 형식 검사 통과와 실제 연주·타점 접촉·영상 출력 검증은 구분해야 합니다.

## 개발 빌드에서 불러오기

1. **캐릭터** 패널의 **VRM 불러오기…**에서 **50 MiB 이하**의 단일 `.vrm` 파일을 고릅니다. 텍스처와 버퍼가 파일 안에 포함되어야 합니다. 파일은 브라우저에서 처리하며 앱이 아바타를 업로드하지 않습니다.
2. 로더는 읽기 전에 VRM 1.0, 필수 시맨틱 본 15개, 본 연결·계층, 유한한 변환 값과 이미지 상한을 검사합니다. 내장 PNG/JPEG 이미지 최대 64개, 한 변 최대 4096픽셀, 전체 6400만 픽셀을 지원합니다. 이는 앱의 입력 제한이며, 최대 크기 모델이 모든 기기에서 원활하게 표시된다는 보장은 아닙니다.
3. 표시된 모델명·제작자·손가락 본 수와 **모델 이용 조건**을 읽습니다. 권리 설정과 추가 조건은 파일에 들어 있는 정보입니다. 선택 항목이 빠졌다면 미기재 상태와 VRM 1.0 명세의 기본값을 함께 표시하며, 누락을 사용 허용으로 해석하지 않습니다. 메타데이터 링크는 자동으로 열거나 조회하지 않습니다.
4. 데모 또는 MIDI를 열고 모델·스켈레톤의 개별 표시 옵션으로 확인합니다. 어댑터는 모델의 팔다리 길이를 측정하고 시맨틱 본 계층을 사용하며 손에 스틱을 연결합니다. 손가락 자세는 해당 본이 있을 때 적용합니다. 접촉 오차 표시는 실제로 렌더링되는 도구 소켓을 측정하지만, 손·의상·몸이 드럼과 전혀 겹치지 않음을 증명하지는 않습니다.
5. **기본 리그**로 내장 시맨틱 스켈레톤에 돌아갑니다. 모델 불러오기와 복원은 현재 MIDI를 선택한 체형에 맞춰 다시 계획하며 원본 타격 시각은 유지합니다.

`.vroid`는 편집 원본으로 로더가 받지 않습니다. VRM 0.x는 감지한 뒤 변환 안내와 함께 거절하며, 파일 이름을 바꿔도 형식이 달라지지 않습니다. 편집 원본을 VRoid Studio에서 VRM 1.0으로 다시 내보내거나, 모델 조건이 허용하는 범위에서 [공식 UniVRM 이전 안내](https://vrm.dev/en/univrm1/migrate_vrm0/)를 따르세요. 임의의 캐릭터 GLB·FBX 등 다른 리그 형식은 이 로더의 구현 범위가 아닙니다. 별도 드럼 부품 GLB 로더는 용도가 다르며 상한은 25 MiB입니다.

## 모델을 구할 곳

| 출처 | 활용 방법 |
|---|---|
| [VRoid Studio](https://vroid.com/en/studio) | 편집 가능한 캐릭터를 만들고 필요한 VRM 버전으로 내보냅니다. 같은 기준에서 체형 두 개를 준비하기에 적합합니다. |
| [VRoid Hub](https://hub.vroid.com/en/) | 모델을 찾고 제작자가 제공한 다운로드·동의 절차를 이용합니다. 모델별 형식과 조건을 확인합니다. |
| [VRM 공식 샘플](https://github.com/vrm-c/vrm-specification/tree/master/samples) | 개발용 공식 샘플을 구합니다. 각 모델의 고지와 내장 설정이 별도로 있습니다. |
| [BOOTH](https://booth.pm/) | 제작자 에셋을 찾습니다. 실제 포함 파일과 개별 약관을 확인합니다. 무료라는 사실만으로 재배포 허용이나 VRM 호환성이 확인되지는 않습니다. |

공식 Hub의 [AvatarSample_A](https://hub.vroid.com/en/characters/2843975675147313744/models/5644550979324015604)와 [AvatarSample_B](https://hub.vroid.com/en/characters/7939147878897061040/models/2292219474373673889)는 현재 **VRM 0.0**으로 표시됩니다. 준비하려는 VRM 1.0 파일과 구분해야 합니다. 두 모델의 [샘플 이용 조건](https://vroid.pixiv.help/hc/en-us/articles/4402394424089-VRoidPreset-A-Z)은 CC0가 아닌 별도 조건입니다.

개발자용으로는 pixiv의 보관된 공식 [ChatVRM 저장소의 AvatarSample_B](https://github.com/pixiv/ChatVRM/blob/b542aa00e19dccf9fc48ba340cf7eee011d2329a/public/AvatarSample_B.vrm)가 별도의 VRM 1.0 파일입니다. [Twist 샘플](https://github.com/vrm-c/vrm-specification/tree/master/samples/VRM1_Constraint_Twist_Sample)과 [Seed-san](https://github.com/vrm-c/vrm-specification/tree/master/samples/Seed-san)도 1.0 후보입니다. 검사한 파일에는 필수 몸통·팔다리 본과 양손 손가락 본이 있습니다. 아래에 해당 파일의 제한된 브라우저 검증을 기록했으며, 이름이 같은 다른 파일까지 보장하는 결과는 아닙니다. Twist에는 자체 VRM Public License 설정이 적용되며 three-vrm 코드의 MIT 라이선스를 따르는 모델이 아닙니다. Seed-san은 크레딧 표시가 필요합니다. 파일 식별값과 출처별 조건은 [엔지니어링 기록](research/vrm-models.md)에 정리했습니다.

## 편집 원본과 실행 파일을 함께 보관하기

`.vroid`는 VRoid Studio의 편집 원본, `.vrm`은 실행 앱용으로 내보낸 모델입니다. 둘 다 보관하세요. 내려받은 `.vrm`이 원래 체형 파라미터를 편집하는 원본을 대신하지는 않습니다. 최신 Studio의 dress-up 기능은 VRM 데이터를 열 수 있으므로, 이 구분을 “Studio에서는 어떤 VRM도 열 수 없다”는 뜻으로 이해하면 안 됩니다. [공식 파일 형식 안내](https://vroid.pixiv.help/hc/en-us/articles/23731198070809-About-file-formats-used-by-VRoid-Studio), [dress-up VRM 지원](https://vroid.pixiv.help/hc/en-us/articles/39513464329881-What-is-VRM)

후속 검증용 체형 두 개는 다음과 같이 준비합니다.

1. Studio에서 새 모델이나 편집이 허용된 원본을 엽니다. 의상·텍스처의 조건도 보관합니다.
2. `.vroid`를 두 파일로 저장합니다. 의상은 비슷하게 유지하고, 하나는 작고 하나는 크게 하되 신체 비율도 다르게 설정합니다. 체형 설정값과 Studio 버전을 기록합니다.
3. **Export VRM**에서 **VRM 1.0**을 고르고 모델·제작자 정보를 입력합니다. `.vroid` 원본 두 개도 유지합니다. [공식 내보내기 안내](https://vroid.pixiv.help/hc/en-us/articles/15760756822297-I-want-to-learn-more-about-the-VRM-export-feature)를 참고하세요.
4. 그립 확인에 필요한 손·손가락 본을 유지합니다. 본 축소 옵션을 사용했다면 내보낸 파일에서 실제로 남아 있는지 확인합니다.

이번 조사에서는 위 절차를 문서화했으며 체형 두 파일을 직접 생성하지는 않았습니다.

## 사용 목적별 조건 확인하기

| 하려는 일 | 확인할 항목 |
|---|---|
| 로컬에서 불러와 평가 | 출처의 다운로드·사용 조건, 사용 가능한 사람, 추가 조건 |
| 렌더링한 연주 영상 공개 | 영상·아바타·모델 이용, 해당되는 경우 상업 이용, 표현 제한, 필요한 크레딧 |
| `.vrm`·텍스처·수정 모델 공유 | 별도의 재배포·수정 조건. 영상 이용 허용만으로 원본 모델의 배포까지 허용되는 것은 아닙니다. |

모델에 내장된 라이선스 링크와 배포 페이지를 함께 읽으세요. [VRM Public License](https://vrm.dev/licenses/1.0/)에는 모델별 설정이 함께 적용됩니다. 외부 의상·텍스처·특정 프리셋에는 추가 조건이 있을 수 있습니다. [VRoid 모델 이용 안내](https://vroid.pixiv.help/hc/en-us/articles/4405813333657-Can-I-use-the-models-created-with-VRoid-Studio-Stable-Ver-for-commercial-purposes)도 참고하세요. 이 저장소의 MIT 라이선스는 자체 코드에 적용되며 캐릭터 에셋의 조건을 바꾸지 않습니다. 영상 내보내기는 모델 크레딧을 자동으로 넣지 않습니다. 모델 조건에 따라 필요한 크레딧을 공개 영상이나 함께 제공하는 출처 표기에 포함하세요.

확보한 모델은 Git에 넣지 않습니다. 개발자는 무시되는 `.local/vrm-test-models/`를 사용하며, 외부 아바타 바이너리를 공개 에셋·테스트 fixture·릴리스 첨부 파일에 넣지 않습니다.

## 현재 검증과 제한

직접 생성한 테스트 fixture로 입력 경계와 메타데이터 처리를 검사합니다. 식별값을 기록한 Twist·Seed-san·ChatVRM AvatarSample_B 파일은 실제 앱 로더·VRM 어댑터·WebGL 재질·Rust/WASM 평가기를 사용하는 로컬 브라우저 검사도 통과했습니다. 모델마다 **30fps 기준 128프레임**을 평가하고 앞뒤 시각을 번갈아 다시 방문했습니다. 그 실행에서 측정한 원본 본 행렬과 자세가 정확히 재현되었고, 배정된 스틱·발바닥 소켓 접점은 평가된 목표와 **0.000001m 이내**의 오차를 보였습니다. 모델별 수치와 범위는 [엔지니어링 근거](research/vrm-models.md#actual-browser-harness-results--2026-10-24)에 있습니다.

제한된 통과 결과입니다. 각 체형에서 킥을 포함한 **테스트 타격 14개 중 11개가 배정**되었습니다. 음표 **41번(로 플로어 탐), 49번(크래시), 51번(라이드)**은 해당 키트·체형 배치에서 도달할 수 없어 진단으로 남았습니다. 원본 타격 이벤트와 시각은 모두 유지했습니다. 14개 타격을 전부 실제로 연주했다거나 의상·피부가 드럼과 전혀 겹치지 않는다는 뜻은 아닙니다. 실제 앱에서는 Twist 샘플의 불러오기·재생·연주자 시점과 모델/뼈대 표시를 확인했습니다. Twist 연주를 합성 오디오가 포함된 923프레임·30.77초 WebM으로 인코딩하는 작업도 완료했습니다. 이는 보고된 인코딩 경로 확인이며 별도 파일 재생 검증은 아닙니다. 브라우저 자동화 제공자가 새 blob 다운로드를 수신하지 못해 별도 플레이어나 ffprobe 검사를 하지 못했습니다. [앱·출력 검증 기록](verification/vrm-studio-unreleased.md)을 참고하세요. 앞서 설명한 통제된 작은 체형/큰 체형 VRoid 두 파일은 아직 만들지 않았습니다. 이 결과는 새 [좌석·페달·하드웨어 보정 묶음](calibration.ko.md) 이전의 것이며, 새 묶음에는 별도의 통합 근거가 필요합니다.

자신의 모델에는 사용할 MIDI를 적용해 좌석 위치, 손의 그립, 실제 렌더링된 스틱 끝, 발·페달과 도달할 수 없는 타점을 확인하세요. 앞뒤로 임의 탐색한 자세와 고정 시각 영상 출력도 비교합니다. 현재 어댑터는 매 자세에서 스프링 상태를 초기화하고 시간 간격 0으로 갱신하며, 동적인 머리카락·의상 시뮬레이션은 결정적 재생 계약에 포함하지 않습니다. 정밀 충돌 회피, 아바타별 수동 그립·발바닥 보정, 물리적으로 정확한 스탠드 길이 조절과 사실적인 손 접촉은 불러오기 성공만으로 검증되지 않습니다.

실제로 마친 검사는 해당 브랜치의 검증 기록과 릴리스 안내를 확인하세요. 이 문서는 새 릴리스나 Pages 배포를 알리는 문서가 아닙니다.
