# Development scope

[GitHub issues](https://github.com/postmelee/drum-vrm/issues) own active scope and acceptance. [Milestones](https://github.com/postmelee/drum-vrm/milestones) group longer-term outcomes; neither a milestone nor an old roadmap authorizes all of its work or a release.

The [work entrypoint](handoff.md) links the current documentation revision and remaining motion work. [Product requirements](../specs/requirements.md) own purpose and invariants; [architecture](../specs/README.md) owns current technical contracts.

The [original plan](https://github.com/postmelee/drum-vrm/blob/66951cd69015e43cfe132a6ba61545b175a25412/docs/plan.md) preserves milestone definitions, the initial issue/dependency map, MVP implementation sequence and subsequent owner priorities. It is historical evidence, not a second live issue board.

## Outcome sequence

| Milestone | Outcome | Routing |
| --- | --- | --- |
| M3 | Natural browser performance synchronized to user WAV | Reproduce input/setup (#23), coherent kit/body fit (#18), mapping and basic sticking (#14 with the basic subset of #20), inspection/data-adoption decision (#21/#23), reusable local setup (#15), WAV preview (#13). |
| M4 | Advanced expression and platform extensions | Broader #20 styles/expression and #22 platform/live-input assessment after the measured browser baseline. |
| M5 | Production and interchange outputs | #16 resolution/FPS/compositing and #19 GLB/VRMA baking. These are deliberately deferred, not browser-quality completion gates. |

M3 quality work runs in parallel where code ownership permits: physical body/hardware,
Rust planning/pose contracts, and browser review/import controls. Contact/support,
clearance, source preservation and sequential/shuffled evaluation are checked throughout.
The existing video encoder is retained without expanding its supported configurations.
A research decision can defer model adoption when runnable artifacts or rights are
unverified; that does not establish a successful learned-model experiment.
