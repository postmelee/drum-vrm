# Reader documentation instructions

Apply [the documentation policy](../specs/policies/documentation.md). This file scopes that policy to reader documentation; do not maintain a second policy body here.

- Read the nearest README before editing. Keep one reader purpose per page.
- Use tutorials for guided learning, how-to for tasks, reference for lookup and explanation for understanding.
- Public pages have reciprocal English/Korean files. Check factual equivalence, examples, limits and availability together.
- Keep adopted contracts and decisions in specs; task plans, historical evidence and proposals belong in mydocs.
- Link the availability reference instead of copying release/PR status across guides.
- Follow the provenance records for third-party assets. Do not hand-edit generated dependency tables or legal notices.
