# 제품 요구사항과 MVP 범위

문서 기준일: 2026-10-24 (Asia/Seoul) · 상태: MVP 구현·검증·GitHub Pages 배포 완료

## 목적과 현재 결정

DAW로 만든 드럼 MIDI를 입력하면 3D 드러머가 연주하는 영상을 만들고, 실제 밴드 커버 영상의 드럼 화면으로 활용한다. 원본 대화의 장기 목표는 캐릭터 외형을 바꿔도 연주 의도를 유지하는 도구다. 현재 MVP는 사용자의 최신 요청에 따라 **MIDI 업로드 → 사전 분석 → 확장 가능한 기본 리그 표시 → 재생 → 영상 다운로드**에 집중한다.

이 문서의 수치와 기술 선택은 사용자가 승인한 개발·인수 기준이다. 구현 여부와 기준 통과는 구분하며 실제 검사 결과 없이 성능이 측정되었다고 표현하지 않는다. 최신 직접 요청이 과거 대화의 제안보다 우선한다. 원본 대화의 항목별 근거는 [대화 맥락](context/source-conversation.md)에 기록한다.

## 승인 경계

사용자는 2026-10-24에 준비된 계획과 MIT 라이선스를 승인하고 MVP 구현·검증·GitHub Pages 배포, 이슈와 문서 갱신을 요청했다. 실제 사용자 메시지는 [승인 기록](approval.md)에 보존한다. M1·M2 범위에서 반복 승인을 요청하지 않으며 M3·M4 전체 구현까지 승인 범위를 확대하지 않는다.

승인된 대상은 MVP 범위, 아래 수용 기준, 아키텍처, 자료 채택 정책, MIT 자체 소스와 배포 방식이다. 현재 핵심 경로의 코드가 구현되었으며 정상 경로·오류·출력 파일과 공개 배포 검증을 진행한다. 배포 성공 증거를 남기기 전에는 예정 URL을 테스트 가능한 공개 서비스로 표시하지 않는다.

## MVP에 포함할 것

| 영역 | 최소 범위 | 완료 결과 |
|---|---|---|
| 파일 입력 | 사용자의 `.mid`/`.midi`를 브라우저 메모리에서 읽기; SMF 0/1 및 PPQ 시간축; 파일 ≤10MiB, 음악 구간 ≤5분 | 드럼 트랙을 고르고 분석 결과 확인 |
| 입력 진단 | 파일 파싱 실패, 드럼 음표 없음, 지원하지 않는 시간 형식, 미매핑 음표, 불가능한 동시 타격 표시 | 실패 이유와 재시도 방법 제공 |
| 사전 분석 | 템포맵 반영, note-on/velocity, 악기 매핑, 손발 배정, 준비·접촉·반동 계획 | 분석 중 상태와 준비 완료 상태가 구분됨 |
| 드럼 범위 | 킥, 스네어, 닫힌/열린 하이햇, 하이햇 페달, 탐 3개, 크래시, 라이드의 기본 GM 매핑 | 기본 밴드 비트와 짧은 필인 표현 |
| 기본 연주자 | 자체 제작한 간단한 관절 리그와 스틱; 양손·양발을 구분하는 앉은 자세 | 외부 캐릭터 에셋 없이 전체 흐름 검증 |
| 리그 확장성 | 안정된 관절 이름, 치수·그립·타점 데이터, 연주 의도와 표시 어댑터 분리 | 향후 VRM을 추가해도 MIDI/계획기를 교체하지 않음 |
| 연주 계획 | 오른손 주도/싱글 킥 기본값, 연타와 동시 타격의 손 배정, 도달성 진단 | 원본 타격 시각을 유지하며 지원 가능한 연주 생성 |
| 재생 | 재생·일시정지·처음으로·구간 탐색, 현재 시간/전체 길이, 고정 카메라와 기본 시점 조절 | 분석 완료 후 사용자가 재생을 시작 |
| 미리듣기 | MIDI만으로 확인 가능한 단순 합성 타격음; 사용자 제스처로 오디오 시작 | 외부 샘플 없이 시각·청각 타이밍 점검 |
| 영상 출력 | 기본 1280×720, 30fps, 단색 배경, 합성 드럼 오디오를 포함한 영상 1종 이상 | 지원 브라우저에서 30초 샘플을 완주한 파일 다운로드 |
| 출력 제어 | 인코딩 가능 여부 확인, 진척도, 취소, 실패 메시지, 완료 후 재시도 | 오류 후 페이지를 다시 열 필요 없이 복구 |
| 배포 | 정적 GitHub Pages, 저장소 경로에 맞춘 자산/WASM URL, HTTPS | 공유한 Pages 주소에서 파일 업로드부터 출력까지 수행 |
| 맥락 유지 | 버전 고정, 출처/라이선스 대장, 결정 기록, 테스트 결과, 다음 작업 | 다른 세션에서도 이슈와 문서만으로 이어서 작업 |

MIDI-only의 소리는 원본 DAW 음색을 재현하는 대신, 자체 합성한 드럼 소리로 연주를 확인하게 한다. **합성 오디오를 포함한 영상 다운로드가 MVP 필수**이며, WAV 첨부와 DAW 음원의 정밀 동기화는 후속 범위다. 사용자가 명시적으로 음소거를 선택할 수는 있지만, 오디오 인코딩 실패를 무음 파일로 바꾸어 성공 처리하지 않는다. 지원되지 않는 오디오/영상 조합이면 출력 전에 제한을 알리고 지원 조합을 선택하게 한다.

인코더는 실행 시 지원을 조회해 MP4/H.264 또는 WebM의 사용 가능한 조합을 선택한다. 특정 형식이 모든 기기에서 된다고 약속하지 않는다. 최소 지원 환경은 구현 시 테스트한 데스크톱 Chromium 계열 버전으로 고정하며, Safari/Firefox는 기능 탐지와 제한 메시지를 검증하고 전체 출력 호환성은 후속 범위로 둔다.

## 시간축과 입력 한계

기본 사전 준비 구간(pre-roll)은 `P=0.5초`, 마지막 반동/소리 여운 구간은 `tail=0.25초`로 확정했다. 프리뷰와 출력은 모두 동일한 준비 구간을 사용한다. 원본 MIDI 시각 `0초` 이전에 자세를 준비하며, MIDI 이벤트 자체의 시각은 바꾸지 않는다. 영상의 `k`번째 프레임에서는 `t_song = k / fps - P`를 평가하고 합성 음원의 타격은 영상 시각 `P + t_hit`에 배치한다.

내보내기 길이는 `ceil((P + songDuration + tail) × fps) / fps`다. 여기서 `songDuration`은 파싱/정규화 결과에서 합의한 음악 타임라인 길이이며 마지막 타격과 유효한 트랙 종료 시각을 포함하는 명시적 값이다. 기본 준비/여운 때문에 출력 길이는 원본 음악 길이와 다르다. 30초 음악은 30fps에서 923프레임, 약 30.7667초의 파일이 된다.

초기 입력 상한은 파일 크기 **10MiB(10,485,760바이트)** 이하, `songDuration` **300초 이하**다. 준비/여운은 300초 상한 계산에서 제외한다. 업로드 전에 크기를, 분석 후 음악 길이를 검사하고 초과 원인을 표시한다. 추가로 트랙 수512개, 파일 전체 이벤트200,000개, 선택한 지원 타격50,000개로 제한한다. 전체 이벤트 수는 파싱 iterator에서 검사한다. 같은 시각 그룹의 처음32개까지만 beam 후보를 확장하고 그 이후 지원 타격은 unresolved 진단과 소리로 보존한다. 이 상한은 비정상적으로 큰 작업량을 제한하기 위한 구현 정책이며, 크기나 길이가 범위 안에 있다는 사실이 모든 MIDI 패턴의 인간다운 연주나 실기기 성능을 보장하지 않는다.

## 데이터와 동작의 불변 조건

- 원본 이벤트의 트랙·인덱스·음표·velocity·시각을 추적 가능하게 보존한다. 동작을 편하게 만들려고 MIDI 타격 시간을 밀거나 흔들지 않는다.
- `NoteOn velocity=0`은 타격으로 세지 않는다. note-off 길이를 팔이 내려가 있는 시간으로 해석하지 않는다. 템포는 곡 전체 단일 BPM으로 간주하지 않는다.
- 드럼 트랙을 항상 채널 10으로 고정하지 않는다. 기본 추정과 사용자 선택을 제공한다.
- 불가능한 타격은 진단과 연결한다. 아무 알림 없이 음표를 버리거나 같은 손을 같은 시각에 두 타점으로 보내지 않는다.
- 타점과 스틱 끝을 기준으로 접촉을 계산한다. 손을 드럼 중앙에 놓는 것만으로 완료 처리하지 않는다.
- 주요 자세는 `evaluate_at(song_time)`로 계산한다. 이전 재생 프레임 수나 화면 FPS에 따라 결과가 바뀌지 않게 한다.
- 표면 외형/렌더링과 `PerformancePlan`을 분리한다. 계획에는 타격 시각, 악기, 타점, 손발, 준비/반동, 진단을 유지한다.
- 브라우저는 사용자가 선택한 파일을 로컬에서 처리한다. 원본 MIDI/WAV/캐릭터 파일을 GitHub나 별도 서버에 자동 업로드하지 않는다.
- 외부 코드·에셋·데이터는 출처, 정확한 버전/커밋, 라이선스, 적용 조건을 기록한 뒤 도입한다. 링크만 조사한 자료와 실제 배포물에 포함한 자료를 구분한다.

| A02 | SMF 0/1, PPQ, 템포 변경 픽스처 | 기대 타격 수와 악기 분류가 일치; 계산 시각의 참조값 대비 오차 1ms 이하 |

| A04 | 잘못된 파일, 빈 입력, SMPTE/SMF 2 등 미지원 입력; 10MiB/300초 경계 | 앱 크래시 없이 원인을 표시; 크기/길이 상한 이하는 허용하고 초과 입력은 거부; 다른 파일을 바로 선택해 정상 분석 가능 |

| A06 | 기본 비트·필인·하이햇 페달; 첫 음표가 0초인 사례 | 양손·양발이 역할에 맞게 움직임; 0.5초 준비 구간으로 첫 타격 전 준비를 보여주고 마지막 타격 후 0.25초 여운을 보존 |
| A07 | 계획된 타격 순간의 접촉 | 기본 키트/리그의 도달 가능한 배정 타격에서 스틱 끝과 목표 타점의 거리 2cm 이하; 원본 시각에서 평가하여 검증 |

| A16 | 리그 확장 계약 | 기본 리그/키트 치수를 데이터로 변경하는 작은 계약 테스트로 계획과 렌더러 분리 확인; VRM 로더 구현은 요구하지 않음 |

성능 측정은 30초·일반 밴드 드럼 패턴을 첫 기준으로 삼는다. 최대 5분 입력과 10MiB 경계, 많은 이벤트, 장시간 프리뷰는 별도 측정 사례로 기록하고, 메모리/분석 시간 목표는 실제 테스트 기기와 파일을 명시한 뒤 결정한다. 근거 없이 모든 파일/기기에서 실시간 처리나 60fps를 보장하지 않는다.

## 구현과 인수 진행 순서

1. Rust 코어/WASM과 웹 셸을 연결하고, MIDI 분석·템포맵의 참조 테스트를 만든다.
2. 기본 드럼 세트·리그와 결정적 타격 궤적을 붙여 30초 재생을 완성한다.
3. 영상 인코딩 스파이크로 지원 브라우저/형식·취소·메모리를 먼저 확정한다.
4. 양손·양발 배정·진단·재생 제어를 통합하고 수용 기준을 검증한다.
5. 라이선스 고지와 운영 문서를 갱신하고 GitHub Pages에 배포한다.
6. 사용자가 실제 DAW MIDI로 확인한 결과를 다음 이슈의 근거로 사용한다.

사용자 승인은 완료되었고 위 범위의 구현과 검증을 진행한다. 현재 Rust/WASM·기본 리그·합성 오디오·UI·고정 FPS export 코드가 있으며, 체크 항목의 존재를 검증 통과로 대신하지 않는다. 이슈 번호와 최종 완료 상태는 저장소 마일스톤과 [handoff](handoff.md)를 따른다.

현재 리그는 기본 체형 하나와 규칙 기반 동작이다. 임의 체형 재보정, 신체 충돌 회피, 상세 주법, WAV/VRM은 후속 범위다. WebCodecs 지원은 실행 중 실제 codec 시험으로 확인하며 Safari·Firefox·모바일 및5분 전체 성능을 사전 보장하지 않는다. 모든 사용자 원본 파일은 브라우저 안에서 처리한다.
