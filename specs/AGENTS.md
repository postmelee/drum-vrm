# Specification maintenance

Apply the root instructions and [documentation policy](policies/documentation.md).

- Keep adopted requirements, contracts, decision rationale and policies here.
- Keep unadopted proposals, work progress and test reports in `mydocs/`.
- Reconcile current contracts with code and related tests when behavior changes.
- Preserve ADR identifiers and historical decision bodies. Change a decision through
  a follow-up ADR and explicit supersession, not a retrospective rewrite.
- Specification prose is English. Preserved Korean ADRs retain their original text.
- A specification or passing validation is never release authorization; use the
  [release policy](policies/releases.md).
