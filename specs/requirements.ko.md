# 제품 요구사항

[English](requirements.md) · **한국어**

## 목적

작성된 드럼 MIDI 파일을 검토 가능한 3D 연주와 출력 영상으로 바꿉니다.
주요 흐름은 로컬 파일 준비, 결정적 재생·탐색, 캐릭터·키트 조절, 고정 프레임 영상
출력입니다. Rust는 음악 이벤트와 동작 계획을, WASM은 브라우저 연결을,
Three.js는 선택된 리그 렌더링을 담당합니다.

이 계약은 현재 체크아웃한 구현을 설명합니다. 공개된 기능은 개발 중인 작업과
배포 릴리스를 구분하는 [프로젝트 README](../README.ko.md)에서 확인합니다.

## 불변 조건

| ID | 요구 동작 |
| --- | --- |
| INV01 | 계획 과정에서 원본 이벤트 식별자, 트랙, tick, 노트, velocity와 음악적 시각을 보존합니다. 동작 실패를 숨기려고 타격 시각을 옮기지 않습니다. |
| INV02 | 사용자가 트랙·채널을 선택할 수 있어야 합니다. 모든 드럼 파트가 MIDI 채널 10에 있다고 가정하지 않습니다. |
| INV03 | 미지원·불가능 이벤트를 보고합니다. 배정할 수 없는 지원 이벤트도 음악 데이터와 합성음을 유지합니다. |
| INV04 | 재생·임의 탐색·고정 프레임 출력에서 같은 절대 곡 시각을 일관되게 평가합니다. |
| INV05 | 연주 의도를 렌더러·아바타와 분리합니다. 아바타 이름별 애니메이션 분기 대신 측정한 의미 기반 신체 치수를 사용합니다. |
| INV06 | 뼈를 늘리지 않고 좌석과 타점을 맞춥니다. 실제 부착 도구의 접촉을 측정하며, 접촉 오차가 거의 0이라는 사실만으로 자연스러운 동작이나 충돌 부재를 입증하지 않습니다. |
| INV07 | 악기 외형과 타격 반응을 음악적 타점·오디오에서 분리합니다. 의도적인 배치 변경은 관련 타점을 함께 갱신합니다. |
| INV08 | 선택한 MIDI·WAV·드럼 GLB·VRM을 브라우저에서 로컬 처리합니다. 사용자 파일, 비공개 모델과 대화 원문은 커밋하지 않습니다. |
| INV09 | 출력 실패를 보고하고 오디오 출력을 암묵적으로 무음 성공으로 바꾸지 않습니다. 무음 영상은 명시적인 선택입니다. |
| INV10 | 소스 코드, 연구, 모션 데이터, 가중치, 모델과 사운드 에셋을 각각의 권리에 따라 관리합니다. |

## 구현된 흐름의 경계

앱은 명시적인 GM/Logic 매핑과 선택적 카운트인·하이햇 해석으로 SMF MIDI를 받고,
[MIDI 해석 계약](architecture/midi-interpretation.ko.md)에 따라 원본 근거를 보존합니다.
제한된 프레이즈 계획기가 타격을 배정합니다. 피아노 롤로 재생·탐색하며 합성 드럼 또는
같은 출력 시간축에 맞춘 로컬 WAV를 사용합니다.

기본 뼈대와 가져온 VRM 1.0 캐릭터는 공통 의미 기반 휴머노이드 경로를 사용하며,
타점별 중립 손목과 악기별 준비 자세를 제공합니다. 좌석·타점 보정과 명시적인 정적
키트 맞춤은 세션에만 유지합니다. 공통 하드웨어를 유지하며 드럼 본체를 교체할 수 있습니다.
출력에는 고정 프레임 브라우저 인코딩과 실행 시 코덱 검사를 사용합니다.

정확한 제한과 좌표·시간 계약은 [엔진](architecture/engine-contract.ko.md),
[리그](architecture/rig-contract.ko.md), [오디오·출력](architecture/audio-export-contract.ko.md)
명세에 있습니다. 이는 공학적 제한이며 허용된 모든 입력에서의 성능 보장은 아닙니다.

## 확장 경계

편집·저장, 임의 휴머노이드 GLB 매핑, 통제된 체형 비교, 측정된 해부학적 관절
제한, 명시적 연주 스타일, 물리적으로 연결된 페달 주법과 표현 동작은 별도 이슈 범위입니다.
현재의 오른손 하이햇·왼손 스네어 선호는 완전한 교차 연주 스타일이나 충돌 솔버가 아닙니다.

주법·표현 설계는 음악, 맞춤, 주법과 표현을 별도 책임으로 유지합니다.
[ADR 0006](../docs/decisions/0006-technique-and-expression-foundation.md)을 참고하세요.
제안된 0–100 움직임 조절과 완전한 heel-up/down 역학은 구현된 조작 기능이 아닙니다.

## 완료 조건의 책임

각 구현 이슈는 관측 가능한 완료 조건, 테스트 사례와 남은 한계를 명시합니다.
검증 기록에는 대상 커밋, 환경, 실행한 검사와 검사하지 않은 범위를 식별합니다.
PR 완료는 공개 배포의 증거가 아닙니다.

기존 U/P/A 식별자와 초기 MVP 범위는
[요구사항 기준 기록](https://github.com/postmelee/drum-vrm/blob/66951cd69015e43cfe132a6ba61545b175a25412/docs/product-requirements.md)에
보존되어 있습니다. 현재 이슈 상태를 별도로 수정하는 두 번째 목록으로 사용하지 않습니다.
