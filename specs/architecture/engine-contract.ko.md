## 입력과 시간

PPQ 시간 방식을 사용하는 엄격한 SMF 형식 0·1을 받습니다. 비동기 형식 2와
SMPTE 시간 분할은 이유를 표시하고 거부합니다. 모든 트랙의 템포 이벤트로 시간
맵을 구성하고, 선택한 트랙·채널로 연주할 노트를 정합니다. 원본 tick을 보존하며
시간 계산에는 정수 마이크로초를 사용합니다. velocity가 0인 note-on은 타격을
발생시키지 않고, note-off까지의 길이가 팔을 유지할 시간을 정의하지도 않습니다.

원본 이벤트 보존, 프로필 선택, 실물 부품 매핑과 의도·제어의 의미는
[MIDI 해석 계약](midi-interpretation.ko.md)에서 정의합니다.

| 제한 | 값 |
| --- | --- |
| MIDI 파일 | 10 MiB |
| 트랙 수 | 512 |
| 전체 해석 이벤트 | 200,000 |
| 선택된 지원 타격 | 50,000 |
| 선택된 곡 길이 | 300초 |
| 평가기에 불러오는 직렬화된 계획 | 128 MiB |
| 직렬화된 수치 리그 프로필 | 64 KiB |

이 값들은 입력과 메모리 사용의 범위를 제한합니다. 모든 기기에서 상한 크기의
입력이 성공적으로 인코딩된다고 실측하여 보장한 값은 아닙니다.

## 계획과 배정

`PerformancePlan` 스키마 2는 원본 이벤트와 해석, 타격, 키트 타점, 진단, 곡 길이,
버전 식별자와 템포·박자 정보를 포함합니다. 타격은 원본 식별 정보, 정수 시각,
트랙·채널·노트·velocity를 보존하며 `pieceId`로 음악적 `instrument`와 별도의
물리적 접촉을 식별합니다. 타점과 손발 배정은 보정·재계획 때 바뀔 수 있는 파생
값입니다. 손발은 배정되거나 명시적으로 미배정 상태가 됩니다. 원본 이벤트 범위,
매핑 선택과 스키마 1 이관은 [MIDI 해석](midi-interpretation.ko.md)에서 정의합니다.

파생된 `contactEvents`와 `hihatMotion`은 계획된 표면 접촉과 절대 시각의 기구 상태를
동작·효과·별도의 실제 마커 검수에서 공유합니다.
[장비 접촉 계약](equipment-contact.ko.md#공통-접촉-기록과-하이햇-상태)이 필드,
재계산과 이동 능력의 한계를 정의합니다.

계획기 `phrase-beam-8-beat-horizon-24-posture-v9`는 후보 8개의 beam 탐색으로 최대 24이벤트와
현재 템포의 4분음표 두 개 길이를 미리 보며, 시간 범위는 0.35–1.20초로 제한합니다.
현재 동시 타격 그룹은 그 범위를
확장할 수 있지만 최대 32이벤트로 제한합니다. 후보마다 미래 타격이 실제로 손발을
점유하고, 현재 그룹만 확정한 뒤 다시 앞을 탐색합니다.

후보 비용에는 최근 손 타격 8개의 제한된 이력을 사용합니다. 빠른 스네어·탐 반복과
여러 악기를 오가는 필인에서 한 손의 장시간 연타를 불리하게 평가합니다. 같은 표면에서
강한 타격 뒤에 약한 타격이 오면 두 번의 반동 후보를 선호할 수도 있습니다.
싱글·더블·파라디들 시퀀스는 좌우 반전과 순환 변형을 포함한 약한 선호 조건이며,
원래 드러머의 주법을 식별하지 않습니다.

후보는 미배정 이벤트 수, 기본 오른손 그루브 역할 이탈 수, 이동·간격·루디먼트 비용
순서로 비교합니다. 하이햇·오픈 하이햇·라이드는 오른손, 그루브 근처의 성긴 스네어
백비트는 왼손을 기본으로 합니다. 4분음표 0.8개 길이(0.15–0.4초로 제한) 안의 헤드
타격은 교대·더블이 가능한 필인/연타 후보로 유지합니다. 이 시간 범위는 연주자의 의도를
복원한 것이 아닌 공학적 선택입니다. 명시적인 손 지정이 우선하며 도달·같은 손의
점유·이동 상한으로 실제 가능성을 판단합니다.

가까운 단일 크래시는 오른손 그루브 역할을 잇되, 마지막 그루브 타격 이후에 헤드
타격이 있었다면 그 선호를 풉니다. 동시에 친 백비트와 하이햇은 그루브를 끊지 않습니다.
필인 뒤에는 두 손을 모두 후보로 두고 직전 타점과 다음 목적지를 비교합니다. 왼손으로
왼쪽 크래시를 치면서 오른손으로 하이햇을 준비할 수 있습니다. 경로를 줄이려고 원본의
왼쪽 크래시를 오른쪽 크래시로 바꾸지 않습니다. 크래시 두 개를 동시에 치면 이벤트
순서·키트 이름에 무관하게 바깥쪽 배정(왼손은 왼쪽, 오른손은 오른쪽 타점)을 선호합니다.
원본 시각과 물리적 타점은 유지합니다. 기본 역할은 양손 하이햇·오픈핸드 연주를
보편적으로 금지하는 규칙이 아니며 명시적 스타일 선택은 후속 범위입니다.
[교육 자료와 설계 근거](../../docs/research/ergonomics-and-sticking.md#groove-ownership-and-post-fill-crashes).

후보 접촉에서 수치 몸통 간격 비용은 강제 조건이 아닌 선호 조건으로 사용합니다.
후보 상한 밖 이벤트도 소리·진단을 유지합니다. 이는 제한된 휴리스틱이며 전체 최적
편곡이나 충돌 없는 동작 경로를 보장하지 않습니다.
최소 재타격 간격 45 ms와 최대 타점 이동 속도 12 m/s는 공학적 휴리스틱이며
생리학 연구의 측정값이 아닙니다. 도달 가능성은 전달된 체형으로 판단합니다.
미지원 노트와 지원되지만 미배정된 타격은 서로 다른 진단입니다.

## WASM API와 포즈 버퍼

| 진입점 | 의미 |
| --- | --- |
| `inspect_midi(bytes)` | 검사·트랙 메타데이터를 JSON으로 반환 |
| `plan_midi(bytes, selectionJson)` | 런타임 동작 곡선을 만들지 않고 원본 계획 해석·배정 |
| `fit_kit(profileJson, kitJson)` | 원본 이벤트를 바꾸지 않고 제한된 정적 키트 맞춤 제안 반환 |
| `ready_pose(profileJson, kitJson)` | 악보 없이 검증된 양손 스네어 기준 자세 반환 |
| `Performance(bytes, selectionJson)` | 유지 중인 기존 연주 경로 생성 |
| `Performance.from_json(planJson)` | 기존 기본 리그 비교 경로 불러오기 |
| `Performance.from_json_with_profile(planJson, profileJson)` | 측정된 수치 체형에 맞게 재배정·평가 |
| `prepared_json()` | Worker 전달을 위해 검증된 계획·프로필과 미리 계산한 동작 곡선 직렬화 |
| `Performance.from_prepared_json(json, expectedMidiHash, expectedProfileJson)` | 계획을 반복하지 않고 준비된 런타임 검증·적용 |
| `plan_json()` | 검증된 결과 계획 반환 |
| `evaluate_at(songTime)` | 월드 위치를 나타내는 float 57개 반환 |
| `evaluate_rig_at(songTime)` | 위치 57개, xyzw 도구 쿼터니언 네 개와 몸통 쿼터니언 한 개, 총 float 77개 반환 |
| `evaluate_hihat_at(songTime)` | 문자 그대로 해석한 노트와 명시적 제어의 공통 절대 시각 하이햇 열림 반환 |
| `inspect_pose_at(songTime)` | 수치 골격 대리 형상의 간격과 뼈 길이 측정값을 JSON으로 반환 |

첫 48개 값은 LH/RH/LF/RF 순서의 네 팔다리에 대해 각각 시작·중간·끝 관절과 도구
접촉점의 XYZ를 담습니다. 골반·가슴·머리는 오프셋 48·51·54에 있습니다.
도구 쿼터니언은 오프셋 57부터 같은 팔다리 순서로, 몸통 쿼터니언은 오프셋 73부터
시작합니다. 유지 중인 위치 57개 API는 이 버퍼를 잘라 반환합니다. 휴머노이드 어댑터는
몸통 회전이 없는 기존 73개 버퍼도 받습니다. 반환 배열은 소유권이 있는 값이며,
소비자는 문서화되지 않은 WASM 메모리 뷰를 유지하지 않습니다.

`RigProfile` 스키마 1은 좌표계 태그, 시작 관절, 분절 길이, 굽힘 기준점, 휴지 상태
끝점, 그립·끝점 오프셋, 접촉 회전과 몸통 기준점을 담습니다. 선택적 `handFrames`는
공통 타점별 손목 솔버에 측정한 전완·손바닥 축과 원하는 손바닥 방향을 제공합니다.
이 필드가 없는 기존 프로필은 고정 방향 동작을 유지합니다. 선택적 `torsoPivot`은
협응 회전에 필요한 측정된 척추 피벗을 제공하며, 없으면 몸통 yaw는 0입니다.
두 필드 모두 스키마 1의 호환성을 유지합니다. 프로필은 계획과 별도로 전달합니다.
계획의 `calibrationId`만으로 프로필을 복원할 수 없습니다.
[리그 계약](rig-contract.ko.md)이 좌표와 부착의 의미를 정의합니다.

## 준비와 Worker 경계

브라우저의 체형 맞춤, 최초 계획, 보정 재계획과 프로젝트 복원은 취소 가능한
Worker에서 실행합니다. 후보를 검증하여 적용할 때까지 기존 장면·평가기를 유지하며
보정·재계획이 실패하거나 취소되면 이전 설정을 보존합니다. 다른 MIDI를 불러오면
준비 전에 기존 악보를 초기화합니다. 렌더링, 절대 시각 평가와 저비용 런타임
적용은 메인 스레드에서 실행합니다.

`plan_midi`는 동작 평가기를 만들지 않고 원본을 파싱·해석합니다. Worker는 최종 체형과
키트를 적용하기 전에 이를 호출하므로 사용하지 않을 기본 체형 동작을 먼저 준비하지
않습니다. 완료된 요청은 초기화한 Worker를 다음 요청에 재사용하며, 실행 중인 요청을
취소하거나 교체하면 종료합니다. 요청 ID와 세대 번호가 오래된 응답을 거부합니다.
원본·프로필이 정확히 일치하면 검증된 준비 후보 하나를 재사용할 수 있습니다. MIDI
계획 후에는 후보의 파생 타점을 요청 당시 배치의 기준점으로 되돌린 정확한 입력도
같은 후보에 연결합니다. 따라서 오디오 사전 확인 후 동작 탐색을 반복하지 않고
같은 후보를 적용합니다. 각 식별 키는 전체 계획·수치 프로필을 포함하고 배치의 모든
필드를 보존하며, 원본 지시·형상·체형 정보가 달라지면 다시 준비합니다. 취소하거나
대체 탐색이 실패하면 후보 재사용을 폐기합니다. Rust는 준비된 후보를 적용할 때마다
여전히 검증합니다.
업로드 파일을 무제한 보관하는 캐시가 아닌 제한된 재사용입니다.

[prepared.rs](../../crates/drum-engine/src/prepared.rs)가 내부 전달 형식 2를 정의합니다.
계획, 수치 프로필, 몸통·팔꿈치·장비 접근 곡선과 FNV-1a 무결성 체크섬을 포함합니다. 적용할 때
엔진·계획기 버전, 예상 원본·프로필 식별 정보, 유한 값, 순서, 곡선 범위, 정확한 제어
시각과 저장된 몸통 회전·장비 피치에서 배정된 타점·페달 도달성을 검사합니다. 다른 자세로
도달할 수 있어도 저장된 타격 자세가 도달하지 못하면 유효하지 않습니다. 장비 경로는 높이·피치 범위, 변화율과
원본 타격 시 높이 보정 0도 확인합니다. 적용 시 검증한 표본을 사용하며 메인 스레드에서
장비 경로 탐색을 반복하지 않습니다. 체크섬은 오래되거나 손상된 데이터를
검출하며 암호학적 서명이 아닙니다. 페이로드 상한은 128 MiB입니다. 실수 값을 정확히
왕복하여 주요 자세와 수치 검사를 보존합니다. 이 임시 전달 형식은
[저장 프로젝트 형식](project-format.ko.md)과 별개입니다.

공동 동작 계획기는 0.1초 격자, 정확한 배정 손 타격과 명시적 카운트인 경계 시각을
합쳐 중복 제거 후 제어 시각을 최대 6,000개 허용합니다. 거의 같은 부동소수점 격자
시각보다 원본 타격 시각을 우선 보존합니다. 초과하면 탐색 테이블 할당 전에 준비 오류를
반환합니다. 선택 구간을 줄이거나 트랙 수를 줄여야 합니다. 해석 단계의 타격
50,000개 제한은 동작 예산 안에 든다는 보장이 아닙니다. 표본과 메모리 범위는
[보정 계약](calibration.ko.md)에서 정의합니다. 별도 장비 접근 경로는 30 Hz 격자와
정확한 배정 손 타격을 합쳐 최대 16,000개 표본을 허용하며, 준비와 전달 역직렬화에서
같은 한계를 적용합니다.

## 결정적 평가

포즈는 검증된 계획, 프로필, 절대 곡 시각의 함수입니다. 순차 재생, 순서를 섞은
탐색, 고정 프레임 출력은 같은 주요 포즈를 만들어야 합니다. 프레임 이력에 의존하는
난수나 누적된 보조 물리가 결과를 조용히 바꾸면 안 됩니다.

측정 프로필 경로에서는 기본적으로 왼손은 스네어, 오른손은 하이햇의 3.5cm 위에서
대기합니다. 같은 실물 부품을 반복하면 그 부품 위를 준비 위치로 사용합니다. 후보가
닿지 않으면 측정한 기준 휴지 위치를 사용합니다. 손의 준비·회복 시간은 타점과 준비
위치 사이 거리를 2.5 m/s로 나누어 각각 0.22–0.65초와 0.18–0.65초로 제한합니다.
두 시간의 합에 0.02초를 더한 값 이내의 타격 간격은 한 번에 직접 연결합니다. 가까운
타점에서는 0.42초 기준을 유지하고 긴 이동의 준비·회복 구간이 겹쳐 서로 끊는 것을
막습니다. 더 긴 간격은 별도 구간 사이에서 준비 자세로 연결합니다. 이 시간은 공학적
휴리스틱입니다. 기존 기본 리그 비교 경로는 공통 휴지 위치를 유지합니다.

Velocity는 들어 올리는 높이와 손목 피치를 조절하며 짧은 간격에서는 시간을 맞추도록
둘을 줄입니다. 현재·다음 velocity는 양 끝점을 고정한 채 직접 이동 구간의 정점을
악센트 뒤에는 앞당기고 악센트 앞에서는 늦춥니다. 정확한 타격 시각에는 타점과 추가
스트로크 피치 0을 유지합니다. 이는 절차적 스트로크이며 학습한 push-pull, 힘
시뮬레이션이나 완전한 관절 제한이 아닙니다.
측정 프로필의 손 이동에서는 들어 올린 중간 끝점과 기준 어깨의 거리가 양 끝점 반경의
보간값보다 작아지지 않게 합니다. 준비 중 안쪽으로 접히는 현상을 줄이는 장치이며
장애물을 우회하는 경로 계산은 아닙니다.

`torsoPivot`이 있으면 계획 단계에서 yaw를 ±0.24 rad로 제한한 12 Hz 몸통 방향 곡선을
미리 계산합니다. 양손 타점, 몸통·전완 대리 형상의 간격과 직전 계획 표본에서의 변화량을
고려해 후보 yaw를 고릅니다. 절대 시각의 부드러운 보간으로 yaw를 정한 뒤, 회전한
어깨에서 원래 월드 타점으로 양팔을 다시 풉니다. 골반과 다리 루트는 고정합니다.
미리 계산한 곡선은 재생 순서나 프레임 속도에 의존하지 않습니다. 배정된 모든 손 타격을
보간된 yaw로 검사하며 도달성을 잃으면 인접 제어점만 감쇠하고 변화율 제한을
전파합니다. 제한된 보정에 실패하면 yaw 0을 대체값으로 사용합니다.
연속적인 중립 손목 계산과 제한된 몸통 계획은 [보정 계약](calibration.ko.md)에서 정의합니다.

`handFrames`가 있는 프로필은 별도로 미리 계산한 팔꿈치 선회 곡선으로 몸통·팔·스틱의
대리 형상을 고려해 양팔을 협응합니다. 회전한 체형과 기존 접촉 경로를 사용하며 타격
배정이나 원본 시각은 바꾸지 않습니다. 표본과 각도의 범위는
[보정 계약](calibration.ko.md)에서 정의합니다. 절대 시각의 보간은 탐색의 결정성을
유지하지만 대리 형상 비용이 충돌 없는 동작을 인증하지는 않습니다.

`inspect_pose_at`은 `scope: "skeletal-proxies"`, `torsoClearanceMeters`,
`armClearanceMeters`, `stickClearanceMeters`, `crossClearanceMeters`,
`geometrySource`, `boneLengthErrorMeters`, `poseFloats`를
반환합니다. 교차 간격은 스틱과 반대쪽 팔·손 사이의 최소 간격이며, 스틱을 쥔
자기 손과의 부착은 허용합니다. 음수 간격은 수치 대리 형상의 겹침을 뜻합니다. 뼈 오차는 네 팔다리의 최대
분절 길이 차이입니다. 이 값은 평가된 수치 포즈를 검사하며 렌더링된 부착 표식의 측정이나
피부·의상·가져온 악기 지오메트리·연속 경로의 간격 보장을 대신하지 않습니다.

타점별 손 좌표계는 [보정 계약](calibration.ko.md), 하이햇 상태와 원본 의미는
[MIDI 해석](midi-interpretation.ko.md)에서 정의합니다. 재생과 출력은
[오디오·출력 계약](audio-export-contract.ko.md)에 따라 선택한 오디오 버퍼를 공유합니다.
