# 로컬 프로젝트 형식

[English](project-format.md) · **한국어**

[project.ts](../../src/project.ts)가 `drum-vrm-project` 스키마 1을 정의합니다.
최대 32 MiB인 로컬 JSON 컨테이너이며 저장·재연결 시 파일을 전송하지 않습니다.
[사용 흐름](../../docs/projects.ko.md)을 참고하세요.

| 필드 | 책임 |
| --- | --- |
| `format`, `schemaVersion`, `engineModuleSha256` | 컨테이너 식별자와 재생에 사용한 정확한 WASM 바이너리 |
| `plan` | 선택된 원본 메시지·해석·제어·원래 시각·손발 배정을 포함한 스키마 2 연주 계획 |
| `selection` | 트랙·채널, 매핑 프로필, 카운트인 선택, 하이햇 정책·열림 값, 제외할 원본 ID와 수동 손 지정 |
| `profile`, `rig`, `calibration`, `kit` | 측정한 공통 휴머노이드 계약, 기본/VRM/FBX 선택, 좌석·손바닥 설정과 물리 배치 |
| `assets` | 종류·표시 이름·SHA-256·바이트 크기·선택적 드럼 부품 ID. 가져오기 URL이나 바이너리가 아님 |
| `appearance` | 포함 프리셋과 부품별 자체/라이브러리/사용자 모델 선택, 마감·명시적 `finishOverride`·크기·회전. 표시용 기본 색상이 있어도 사용자가 변경하지 않았다면 라이브러리·가져온 모델의 원래 재질을 덧칠하지 않습니다. |
| `camera`, `hitResponse`, `view` | 실제 카메라 위치·목표·시점, 반응, 테마·배경, 표시와 피아노롤 확대 |
| `audio`, `outputTime` | 합성/WAV 선택, MIDI 기준 WAV 오프셋·음량과 출력 시간축의 재생 위치 |

프로젝트는 선택된 MIDI 메시지와 파생 동작 데이터를 보존합니다. 공개용으로 정보를
줄인 검수 보고서가 **아니므로** 설정만 포함된 파일처럼 공개하면 안 됩니다.
원본 입력 파일·오디오 PCM·모델 도형·에셋 권한은 포함하지 않습니다.
해시는 같은 내용의 재연결을 확인하며 저자나 재사용 권리를 증명하지 않습니다.

## 복원 절차

브라우저는 스키마·버전, 유한하고 범위 안에 있는 설정, 필수 부품 식별자,
중복 없는 에셋 참조와 선택한 정책·배치가 계획과 일치하는지 검사합니다.
참조 파일이 없으면 현재 세션을 유지합니다. 재연결은 SHA-256·바이트 크기를 비교하며
이름이 바뀐 같은 파일은 허용하고 이름만 같은 수정 파일은 거절합니다.
계획에 선택된 메시지가 있어도 이후 트랙·매핑 수정에 원본이 필요하므로 MIDI를 요구합니다.
WAV·VRM·FBX·선택 이미지·사용자 GLB는 프로젝트에서 사용한 경우에만 필요합니다.
포함 모델은 앱 자체 프리셋 에셋에서 불러옵니다.

적용 전에는 일치한 MIDI를 다시 파싱해 원본 이벤트·시간 맵·해석·제어를 저장한
계획과 비교합니다. 실제 리그를 구성하고 보정을 다시 적용해 체형 측정값을 비교하며,
Rust에서 연주를 검증·재구성하고 WAV를 디코딩하며 모든 사용자 드럼 도형을 준비합니다.
사전 검증이 실패하면 표시 중인 세션은 바꾸지 않습니다. 이러한 비동기 검사를 모두
마친 뒤에만 설정·장면·오디오를 교체합니다.

계획·리그 유효성은 Rust가 결정합니다. JSON 파싱 성공만으로 저장된 손발 배정·Velocity·
제어를 신뢰하지 않습니다. 원본·매핑·의도 경계는 [MIDI 해석](midi-interpretation.ko.md),
WAV 정렬은 [오디오·출력](audio-export-contract.ko.md)에서 정의합니다.


저장 프로필에는 메시 정점 대신 선택적인 수치형 신체 영역이 포함됩니다. 브라우저는 범위를 검증하고 다시 측정한 프로필을 비교하며, 프로젝트 복원 중 자동 배치 보정을 다시 실행하지 않습니다. 형상 정보가 없는 이전 파일은 원래 스키마 해석을 유지하지만 정확한 엔진 해시 호환성은 여전히 필요합니다.

## FBX 프로젝트 설정

스키마 1은 `rig: "fbx"`와 필수 `fbx` 객체도 받습니다. 이 객체는 `bones`(의미
이름과 안정적인 자식 인덱스 경로), `metersPerUnit`, `textures`(재질 순회
인덱스와 정규화한 이미지 파일명)를 담습니다. 기본/VRM 프로젝트는 이 객체를
생략합니다. 원본 FBX는 `fbx` 참조 하나, 선택한 PNG/JPEG는 각각 `fbxTexture`
참조를 가집니다. 전체 파일 참조 최대 77개, FBX 이미지 최대 64개·합계 50 MiB를
허용합니다. 본·단위·이미지 범위는 [FBX 계약](rig-contract.ko.md#fbx-불러오기)이 소유합니다.

리그와 원본 종류 불일치, 대소문자를 통일한 이미지 이름 중복, 대응 이미지 참조가
없는 재질 연결은 거절합니다. 해시·크기로 일치 여부를 확인한 후 저장 목록의 원래
파일명을 복원하므로 이름만 바뀐 파일도 텍스처 연결을 복원합니다. 로더·본 연결·
실측 프로필을 다시 검증하며 기존 복원 절차가 성공한 뒤 설정을 적용합니다.
기존 기본/VRM 스키마 1 프로젝트는 FBX 설정 없이 계속 허용합니다.

## 호환성과 검증

스키마 1은 저장한 WASM SHA-256과 같은 계획기 버전을 요구합니다. 다르면 정확한 복원을
막고 원래 앱 빌드를 사용하거나 원본 MIDI를 다시 준비하도록 안내합니다.
조용한 엔진 이관·에셋 대체·자동 다운로드·업로드는 없습니다. 원본 에셋은 로컬 파일
선택기로 다시 연결합니다. 엔진 해시만으로 렌더러·브라우저·하드웨어·모델 로더 리비전이
달라도 같은 픽셀이 나온다고 보장할 수는 없으므로 검토할 때 같은 앱 빌드를 보관하세요.

검증은 재열기 전후의 원본 시각·해석, 임의 시점 자세, 카메라·설정, WAV 정렬을
비교해야 합니다. 모든 이벤트가 보존된 프로젝트를 다시 여는 것이 자연스러움이나
피부 간격까지 증명하지는 않습니다. 영상 품질 확장과 버전 간 이관은 별도 작업입니다.
