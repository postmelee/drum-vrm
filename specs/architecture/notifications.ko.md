# 알림과 간결한 설정 메뉴

[English](notifications.md) · **한국어**

**제안 설계이며 아직 제품 동작이 아닙니다.** [이슈 #62](https://github.com/postmelee/drum-vrm/issues/62)가
구현 범위와 완료 기준을 관리합니다. [인터랙티브 시안](../../docs/design/notifications.html)은
가상 상태로 배치·문구·모션을 보여주며 실제 파일이나 엔진을 처리하지 않습니다.
#44의 조작 중심 메뉴 방향을 확장합니다.

## 정보의 표시 위치

| 정보 | 위치 | 예시 |
| --- | --- | --- |
| 작업 결과 | 공통 토스트 하나 | MIDI 불러오기 완료 / Songsterr 매핑 적용 |
| 오래 걸리는 작업 | 같은 토스트 갱신, 작업 위치에 취소 유지 | 연주 준비 중… |
| 현재 선택·상태 | 조작부의 값 또는 짧은 상태 | 매핑: Songsterr, 오디오: 합성음 |
| 미해결 조건 | 지속 배지·필드 상태와 토스트 한 번 | 매핑 확인 필요, 분석 · 2 |
| 근거·계측 | 필요할 때 여는 분석 | 후보별 지원 수, 원본 음표, 미배정 타격 |
| 참고 설명 | 접힌 도움말 또는 문서 | 오프셋 부호, 매핑·버전 제한 |
| 입력 오류 | 해당 필드의 짧은 수정 안내 | 5~100%로 입력하세요 |
| 저작자·이용 조건 | 찾을 수 있는 모델·라이선스 영역 | 제작자와 사용 조건 |
| 스크린 리더 설명 | 기존 접근성 연결 | 피아노 롤 악기별 개수와 단축키 |

일반 메뉴에는 제목·라벨·현재 값·동작을 남깁니다. 결정에 필요한 경우에만 그룹당
짧은 도움말 한 문장을 허용합니다. 분석 출력, 주의사항, 구현 설명, 작업 이력을
`.hint` 문단으로 붙이지 않습니다. 긴 문단을 그대로 토스트로 옮기지도 않습니다.
색상만으로 라벨을 대신하지 않습니다.

## 배치와 외형

- 데스크톱: **연주 화면 내용 영역의 우측 상단**, 카메라 도구 아래에서 위·오른쪽
  16px 안쪽에 둡니다. 너비 344px이며 남은 공간을 넘지 않습니다. 메뉴가 열리면
  연주 화면과 함께 기준점이 이동하여 설정을 가리지 않습니다. 메뉴를 닫으면
  앱 내용 영역의 우측 상단에 놓입니다.
- 700px 이하: 도구 모음·카메라 영역 아래에 한 장만, 좌우 12px와 안전 영역 여백을
  적용합니다. 재생 조작부나 피아노 롤 위에 놓지 않습니다. 좁은 화면의 메뉴 일부와
  잠시 겹칠 수 있으나 닫기 조작은 항상 접근할 수 있어야 합니다.
- 카드: 모서리 8px, 위·좌우 여백 14px, 아래 여백 8px, 테두리 1px, 절제된 그림자, 내부 간격 10px.
  기존 밝은·어두운 테마 토큰을 사용합니다. 불투명 배경에 제목 14px, 선택 설명
  12~13px를 사용하며 글자 뒤에 흐림·반투명 효과를 넣지 않습니다.
- `src/style.css`의 시스템 글꼴과 `--bg`·`--surface`·`--control`·`--border`·
  `--text`·`--muted`·`--active`·`--focus`를 재사용하며 별도 녹색 계열 테마를
  만들지 않습니다. 동작 문구는 선택 색상인 파랑(`--focus: #3274c8`), hover·focus
  배경은 `--active`를 사용합니다. 어두운 테마에서는 파랑 65%와 글자색 35%를
  섞어 같은 색 계열을 유지하면서 동작 문구의 가독성을 높입니다.
- 18px 선형 SVG로 통일합니다. 성공은 원 안의 체크, 확인 필요는 삼각형 안의
  느낌표, 실패는 원 안의 X, 일반 안내는 원 안의 정보 아이콘입니다. 경고는 호박색,
  실패는 앱의 오류 빨강(`#cf4335`)을 쓰고 어두운 배경에서는 밝게 조정합니다.
  색뿐 아니라 모양으로 구분하며 클릭 가능한 문구는 심각도와 관계없이 파랑입니다.
- 구조: 18px 상태 아이콘, 짧은 제목, 필요할 때 짧은 보충 문장, 동작 최대 하나,
  항상 보이는 닫기. 상태색은 아이콘·강조부에만 사용합니다. 동작·닫기 터치 영역은
  데스크톱 32px 이상, 터치 화면 44px 이상입니다.
- 데스크톱에서 제목 한 줄·보충 설명 두 줄 이하를 목표로 씁니다. 좁은 화면과
  200% 확대에서는 자연스럽게 줄바꿈하며 복구에 필요한 내용을 잘라내지 않습니다.
  자세한 정보는 동작을 눌러 확인합니다. 남은 초·카운트다운 배지는 쓰지 않습니다.

## 문구와 결과 예시

| 상황 | 제목 / 선택 설명 | 동작 |
| --- | --- | --- |
| MIDI 준비 성공 | MIDI를 불러왔습니다 / Songsterr 매핑 · 1,513개 타격 | MIDI 설정 |
| 동작 미배정이 있는 준비 완료 | 연주 준비 완료 · 동작 2개 확인 / Songsterr 매핑 적용 | 분석 보기 |
| 매핑 해석 동률 | 드럼 매핑을 확인해 주세요 / General MIDI로 임시 설정했습니다 | 매핑 선택 |
| 미지원 음표가 남음 | 일부 음표를 매핑하지 못했습니다 | 분석 보기 |
| 사용할 매핑 없음 | 드럼 매핑을 찾지 못했습니다 | MIDI 설정 |
| 파일 파싱 실패 | MIDI를 읽지 못했습니다 / 다른 .mid 파일을 선택해 주세요 | 파일 선택 |
| WAV 적용 | WAV를 적용했습니다 | 없음 |
| 프로젝트 저장 | 프로젝트를 저장했습니다 | 없음 |
| 영상 준비 | 영상이 준비됐습니다 | 다운로드 |
| 배치 맞춤 완료 | 드럼 배치를 맞췄습니다 | 유효할 때만 되돌리기 |

작업 결과와 가장 중요한 경고를 완료 토스트 하나로 합칩니다. 가져오기 한 번에
‘매핑 선택’·‘오디오 합성’·‘준비 완료’·‘경고 2개’를 별도 카드로 만들지 않습니다.
무대 상태는 대기 / 준비 중 / 준비 완료 / 확인 필요로 짧게 남깁니다. 매핑 후보를
고른 것만으로 전체 준비 성공을 알리지 않습니다. 재생·일시정지·탐색·카메라 전환·
일반 슬라이더 조작에는 토스트를 띄우지 않습니다. 첫 실행의 배경 초기화 성공도
사용자가 요청한 작업처럼 알리지 않습니다.

## 수명과 동시 알림

| 종류 | 자동 닫힘 | 남겨 둘 복구 정보 |
| --- | --- | --- |
| 성공 | 4초 | 해당 위치의 결과 |
| 취소를 포함한 일반 안내 | 5초 | 현재 작업 상태 |
| 사용 가능한 결과가 있는 경고 | 8초 | 배지·분석 항목 |
| 오류 또는 선택 필요 | 자동으로 닫지 않음 | 해결할 때까지 필드·작업 상태 |
| 진행 중 | 자동으로 닫지 않음, 400ms 이후 표시 | 실제 취소 조작, 임의 진행률 금지 |

작업 하나에 고정 ID 하나를 부여하고 진행 → 성공·경고·오류를 같은 자리에서
갱신합니다. 빠른 작업은 진행 알림을 생략합니다. 단계가 바뀌어도 진입 모션이나
카드를 추가하지 않습니다. 완료 상태가 실제로 보인 뒤에 닫힘 시간을 계산합니다.
마우스를 올리거나 키보드 포커스가 있거나 문서가 숨겨지면 남은 시간을 멈추고,
이후 이어갑니다. 진행 카드 닫기는 작업 취소가 아닙니다. 닫았어도 최종 결과는
한 번 알립니다. 취소 뒤 늦게 도착한 성공은 무시하고, 새 파일을 열면 이전 파일의
동작과 결과 콜백을 무효화합니다.

데스크톱 최대 세 장, 좁은 화면 한 장을 표시하고 간격은 8px입니다. 표시 중인
순서를 유지합니다. 같은 작업 ID를 먼저 합치고, 오류·필수 선택 → 경고 → 진행 →
성공·일반 안내 순으로 대기열을 처리합니다. 서로 다른 알림 최대 8개를 대기시킵니다.
초과한 성공·일반 안내는 최근 기록으로 합칠 수 있지만 오류는 토스트 자리가 없어도
미해결 배지와 알림 목록에서 확인할 수 있어야 합니다.

도구 모음의 작은 알림 버튼으로 현재 세션의 최근 완료 결과 20개를 엽니다.
상시 사이드 패널을 추가하지 않으며 프로젝트나 localStorage에 저장하지 않습니다.
현재 작업의 진행·미해결 상태는 이 개수 제한과 별도로 유지합니다. 닫기는 표시를
확인했다는 뜻이며 문제 해결이 아닙니다. 이전 파일 기록에는 더 이상 유효하지 않은
재시도·되돌리기·다운로드 동작을 두지 않습니다.

## 모션과 접근성

- 목적은 차분한 결과 확인과 명확한 다음 동작입니다. 튀기기·흔들기·축하 효과·
  배경 맥동·계속 움직이는 장식은 사용하지 않습니다.
- 등장: 220ms, `cubic-bezier(.2,0,0,1)`, Y −8px → 0, 불투명도 0 → 1.
  그림자는 카드와 함께 자리 잡습니다. 퇴장: 150ms, `cubic-bezier(.3,0,1,1)`,
  불투명도 0과 Y −4px. 카드 사이 이동은 transform으로 180ms입니다.
- 동작 줄이기: 이동·카드 재배치 모션 없이 즉시 또는 100ms 이하 페이드.
  진행 표시는 회전 대신 정적인 문구를 씁니다. 레이아웃 수치를 애니메이션하거나
  연주 중 별도의 배경 장식 모션을 시작하지 않습니다.
- 완료 알림은 공통 polite 낭독 영역 하나, 진행을 막는 실패에만 별도 assertive
  영역을 씁니다. 보이는 카드를 추가 live region으로 만들지 않습니다. 중복 낭독,
  진행 단계마다 낭독, 과거 기록을 열 때 재낭독하지 않습니다.
- 토스트가 포커스를 빼앗지 않습니다. 동작은 일반 버튼입니다. Escape는 토스트
  조작에 포커스가 있을 때만 그 카드를 닫아 기존 메뉴 Escape와 충돌하지 않습니다.
  포커스된 카드를 닫으면 다음 알림 조작 또는 알림 기록 버튼으로 이동합니다.
  동작 실행 시 해당 설정이나 제목에 포커스를 옮깁니다.
- 필드 라벨·단위·입력 오류·선택 매핑·미해결 배지는 일시적 알림 밖에 남깁니다.
  `.midi-roll-sr`와 `aria-describedby`를 보존합니다. 복사된 접근성 출력에 포함된
  긴 피아노 롤 설명은 이미 화면에서 숨겨진 정보입니다.

## 구현 경계와 이전 계획

향후 단일 `NotificationCenter`가 저장소·시간·대기열·낭독·렌더링을 관리합니다.
호출자는 작업 ID, 파일·프로젝트 범위, 심각도, 번역 키·인자, 선택 동작 ID,
선택 진단 참조를 갖는 타입화 이벤트를 보냅니다. 원시 HTML·예외 전문·파일명에
따른 분기를 전달하지 않습니다. 기존 번역 바인딩으로 언어 전환 시 시간 초기화나
기존 결과의 재낭독 없이 문구를 바꿉니다. 범위 검사로 오래된 콜백을 거부하고
동작을 비활성화합니다. 작업 조정 지점에서 중복을 합치며 `renderDiagnostics()`는
결과 알림을 발생시키지 않습니다.

| 기존 영역 | 변경 계획 |
| --- | --- |
| `notify()` / `#toast` | 공통 센터와 상단 기준 영역으로 교체 |
| `#message` 하단 띠 | 중복 결과 문단 제거, 짧은 무대 상태 유지 |
| `#automatic-mapping`, `#mapping-evidence` | 결과는 토스트, 후보 표는 분석, 선택값은 조작부에 유지 |
| `#source-summary` | 주의가 필요할 때 분석 배지·링크만 표시 |
| `#project-message`, `#character-message`, `#calibration-message`, `#model-message`, `#arrangement-status` | 결과는 토스트, 현재 상태는 짧은 값, 입력 수정은 필드 옆으로 개별 검토 |
| `#wav-info`, `#fit-state` | 짧은 현재 상태 유지, 완료·오류 문구는 공통 센터로 |
| 상시 파일·모델 주의 설명 | 접힌 도움말 한 곳으로, 저작자 표시는 보존 |
| 출력 상태 | 내보내기의 실제 진행·취소, 토스트 하나 갱신, 다운로드 링크 유지 |

모든 `.hint`나 `role="status"`를 일괄 삭제하지 않습니다. 누락된 프로젝트 에셋,
미적용 설정, 맞춤 실패는 토스트가 사라져도 찾을 수 있어야 합니다. 매핑 경고를
동작 실패라고 부르지 않습니다. 이 UI 이전으로 Rust 해석·계획은 바뀌지 않습니다.

## 구현 완료 기준

정상·부분·모호·실패 가져오기, 취소와 빠른 파일 교체, 작업당 결과 한 번, 대기열
초과, 닫은 뒤 복구 정보, 오래된 동작 방지, hover·focus·탭 숨김 시 시간 정지,
키보드 라우팅, 중복 낭독 없음, 영어·한국어, 밝은·어두운 테마, 동작 줄이기,
200% 확대, 데스크톱 메뉴 열림·닫힘 및 390px 좁은 화면을 확인합니다.
실제 화면 증거를 남기고 제어 가능한 타이머로 수명 동작을 검사합니다.
문서 검사 통과만으로 제품의 이 동작을 검증했다고 주장하지 않습니다.
