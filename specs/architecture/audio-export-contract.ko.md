# 오디오·재생·출력 계약

[English](audio-export-contract.md) · **한국어**

## 공통 시간축

원본 MIDI 시각은 바꾸지 않습니다. 출력에는 준비 구간 0.5초와 종료 후 구간
0.25초를 더합니다. 출력 프레임 `i`의 곡 시각은 `i / 30 - 0.5`입니다.
출력 프레임 수는 `ceil((0.5 + sourceDuration + 0.25) * 30)`이므로 원본 곡이
30초이면 923프레임이 됩니다. 합성 오디오와 가져온 WAV의 곡 시각 배치에도
같은 시간 이동을 적용합니다.

브라우저 시간 상수의 기준은 [src/types.ts](../../src/types.ts)이며,
[Rust 모델](../../crates/drum-engine/src/model.rs)에도 반영합니다. 향후 시간 규칙을
바꾸면 미리보기·합성·출력·경계 검사를 함께 변경해야 합니다. 표현 동작 때문에
이 구간을 암묵적으로 늘리거나 잘라서는 안 됩니다.

## 소리와 재생

[synthesis.ts](../../src/synthesis.ts)는 지원 타격으로 결정적인 48 kHz 스테레오
PCM을 생성합니다. 사용자의 DAW 샘플이나 WAV 믹스를 재현하는 기능은 아닙니다.
합성 워커가 UI 스레드 밖에서 오디오를 준비합니다. 지원되지만 미배정된 타격도
소리는 유지합니다. 재생 중에는 Web Audio의 시계를 사용하고, 일시정지·탐색 상태는
같은 절대 시간축에서 평가합니다.

오픈 하이햇 소리는 원본 시작 시각을 유지하면서 다음 닫힌 하이햇·페달 타격 또는
명시적 닫힘 제어에서 끊습니다. 근사한 초크 동작이며 velocity별 레이어나 부분 개방
샘플 재생은 아닙니다. 제어의 의미는 [MIDI 해석 계약](midi-interpretation.ko.md)에 있습니다.

## 로컬 WAV 대체

[wav.ts](../../src/wav.ts)는 브라우저 디코딩 전에 로컬 RIFF/WAVE 파일을 검증합니다.
비압축 PCM 8/16/24/32비트 또는 IEEE Float 32비트와 이에 해당하는
WAVE_FORMAT_EXTENSIBLE 하위 형식을 받습니다. 입력은 모노·스테레오, 8–192 kHz,
최대 100 MiB·300초입니다. 압축 WAV, RF64, 여러 data 청크, 유한하지 않은 float
샘플, 잘못된 크기·전송률·프레임 정보와 다른 채널 구성은 거부합니다.

`loadLocalWav(file)`은 48 kHz `AudioContext`로 한 번 디코딩하고 실제 길이·채널과
샘플의 유한성을 확인한 뒤 디코더 컨텍스트를 닫습니다. 시간 이동 전 원본 버퍼는
로컬에 그대로 유지합니다. 모노는 양쪽 스테레오 채널에 똑같이 복사합니다.
음량 정규화, 리미터, 스템 추출이나 합성 드럼과의 믹싱은 적용하지 않습니다.

`alignWavToPlan(source, plan, offsetSeconds)`은 정렬된 스테레오 버퍼와 잘림·무음
정보를 반환합니다. 오프셋은 −300…300초의 유한한 값입니다. 부호는 곡 시각을
기준으로 하며 양수는 WAV 첫 샘플을 늦춥니다. MIDI 시각은 옮기지 않습니다.
정수 출력 샘플 이동량은 다음과 같습니다.

`round((PRE_ROLL + offsetSeconds) * SAMPLE_RATE)`

+0.25초이면 원본 첫 샘플이 출력 0.75초에, −0.25초이면 준비 구간 안인 출력
0.25초에 놓입니다. 출력 0보다 앞선 샘플만 앞부분에서 잘립니다. 고정된 영상 끝
이후의 샘플도 자르고 오디오가 없는 출력 구간은 0으로 채웁니다. 버퍼 길이는 항상
영상 프레임에 맞춰 반올림된 길이와 같습니다. 복사된 길이, 앞·뒤 잘림, 앞·뒤 무음,
샘플 단위로 반올림된 실제 오프셋을 반환하며 겹치는 구간이 없는 경우도 표시합니다.
UI는 잘림과 겹치는 구간이 없다는 사실을 숨기지 않고 안내합니다.

미리보기와 출력은 같은 정렬 버퍼를 사용합니다. WAV를 불러오면 합성음을 대체하며,
제거하면 합성음으로 돌아갑니다. 오프셋을 다시 적용할 때는 변경하지 않은 원본에서
시작하므로 재샘플링이나 잘림이 누적되지 않습니다. 계획이 바뀌면 원본을 새 길이에
맞춰 다시 정렬합니다. [로컬 프로젝트](project-format.ko.md)는 오프셋을 보존하며 같은 WAV 파일을 다시 연결해야 합니다. 무음 출력은 별도 선택입니다.
조작 방법은 [출력 안내](../../docs/export.ko.md)를 참고하세요.

## 인코딩

[export.ts](../../src/export.ts)는 실제 경과 시간에 맞춰 화면을 녹화하는 대신,
처리 속도를 조절하며 1280×720, 30 fps로 렌더링합니다. 후보 프로필은 실제 지원
여부에 따라 MP4 H.264/AAC, WebM VP9/Opus, WebM VP8/Opus 순서입니다.

오디오 프로필을 제공하기 전에 실제 설정으로 짧은 A/V 인코딩을 수행하고 결과를
역다중화·디코딩합니다. 디코딩된 시작 시점과 오디오 길이가 기대 시간축과 한 프레임
이내로 일치하는지 검사하며, 최종 오디오 길이도 확인합니다. API가 있다는 사실만으로
코덱 호환성을 판단하지 않습니다. 미지원 코덱 때문에 오디오 출력을 조용히 무음 파일로
바꾸면 안 됩니다. 무음 출력은 사용자가 별도로 선택한 경우에만 적용합니다.

코덱 검사와 인코딩 중 취소를 지원합니다. 완료·실패·취소 시 프레임, 인코더와 버퍼를
정리합니다. 브라우저 flush에는 정리 시간이 필요할 수 있으므로 즉시 강제 종료를
보장하거나 중단된 결과를 완성 파일로 표시하지 않습니다.

## 자원과 호환성 제한

렌더러는 모든 원시 영상 프레임을 배열에 쌓지 않습니다. 다만 PCM과 인코딩된 파일은
메모리에 남습니다. 5분 스테레오 Float32 PCM 한 벌만 약 110 MiB이며 복사본과
인코딩 데이터가 추가됩니다. WAV는 디코딩한 원본과 정렬된 출력 버퍼를 유지하고,
디코더 임시 메모리와 인코딩 데이터도 필요합니다. 정렬은 출력 버퍼에 직접 쓰므로
세 번째 PCM 전체 복사본을 별도로 유지하지는 않습니다.
입력 상한이 모든 기기의 최대 메모리나 최장 곡 출력
성공을 보장하는 것은 아닙니다.

WebCodecs에는 보안 컨텍스트와 브라우저·OS가 지원하는 코덱 조합이 필요합니다.
로컬 인코딩 결과, 내려받은 파일의 독립 디코딩, 공개 사이트 검사는 서로 다른
증거 수준입니다. 연결된 이슈나 검증 보고서에 실제 수행한 검사, 대상 커밋, 환경과
남은 한계를 정확히 기록합니다.

과거 코덱 지연 측정은 [v0.1 검증 기록](../../docs/verification/mvp-0.1.md)에 있습니다.
그 결과를 모든 AAC 인코더로 일반화하거나 원본 MIDI 시각을 이동하는 근거로 사용하면
안 됩니다.
